what it's for

Three protocols. One window.

If someone has given you an API to work with, orderer lets you call it, see exactly what comes back, save the calls that turn out to be useful, and find them again later.

HTTP

The common one

Fetching and sending data over the web: GET, POST, PUT, PATCH, DELETE and the rest, with JSON, form, file-upload and GraphQL bodies.

WebSocket

Stays open

A connection that stays open, where messages arrive continuously — live prices, chat, notifications.

gRPC

Between servers

A faster format often used between servers inside a company. Works from the server's own description or from .proto files, with no code generation.

why not just use postman

Most people open an API client to do one thing.

Send a request and look at the response. If that's you, you're running a large piece of software to use a small part of it. orderer is what's left when you keep only that part.

Nothing to install first

No account, no sign-up, nothing but the app itself. Under 200 MB on disk.

No account, ever

There's no sign-in screen, because there's no server to sign in to. The app only talks to the servers you point it at.

Ordinary files

Collections save as readable, indented JSON in ~/.orderer/collections/. Put them in Git, diff them, email them.

Nothing behind a plan

No paid tier, no request cap, no seat count. The whole app is what you get.

All three, one place

HTTP, WebSocket and gRPC as three tabs in the same window, sharing variables, collections and history.

Answers when it's slow

Every response breaks timing into DNS, connect, TLS handshake, TTFB and download — plus TLS version, cipher and cert expiry.

What it deliberately doesn't do

  • —Test scripting. No code before or after a request, no pass/fail checks.
  • —Collection runner. Requests go one at a time, by hand — no CI integration.
  • —Mocks, monitors, docs. None of the platform features around the request itself.
  • —Team collaboration. Sharing means sending someone a file.
  • —OAuth 2.0 flow. Bearer, Basic and API keys work; get the token elsewhere and paste it in.
  • —Cookie jar. Cookies are shown, not stored or replayed automatically.
  • —Request chaining. Copy a token into an environment variable yourself.
  • —Code generation. No curl command, no snippet, on request.
honest note

An honest list, so you can tell in one minute whether this fits your work. If you need any of the above, orderer is the wrong tool — Postman or Bruno will serve you better.

Windows and Linux builds are newer than macOS and haven't seen the same mileage yet. orderer isn't notarised by Apple either, so macOS shows a first-launch warning — that's a paid Apple program, not a statement about the app.

compare

Where it sits

orderer's niche is narrow on purpose: the smallest thing that can send an HTTP, WebSocket or gRPC request properly and remember the answer.

ToolScopeAccountStorage
orderer HTTP + WebSocket + gRPC, deliberately narrow None, ever Plain JSON files on disk
Postman Everything — mocks, monitors, docs, team workspaces Required, cloud sync Proprietary, synced
Bruno HTTP-first, closest in philosophy None Plain files, Git-friendly
Insomnia Comparable scope to Postman Nudged over time Proprietary, synced
curl / HTTPie Scriptable, no interface at all None Whatever you script
Paw / RapidAPI Native Mac app, polished None Paid
install

macOS, Windows, or Linux

That's the entire requirements list. No Node.js, Python, Java, Docker, or account to set up first.

macOS

Apple Silicon or Intel, via Homebrew.
brew tap donghquinn/orderer
brew install --cask orderer

Windows

Windows 10+. Unsigned — SmartScreen will warn once.
